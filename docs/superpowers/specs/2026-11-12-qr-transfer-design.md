# Перенос аккаунтов по QR-коду — дизайн

Дата: 2026-11-12. Статус: согласован.

## Зачем

Сайт показывает QR-код для 2FA один раз. Пользователь сканирует его расширением,
а позже хочет добавить тот же аккаунт на новый телефон (Google Authenticator,
Aegis, 2FAS…). Сейчас расширение этого не умеет: «Поделиться» даёт временную
ссылку с готовыми кодами без секрета — это другой сценарий. Предыдущее
расширение пользователя («Authenticator») показывало QR аккаунта по кнопке
поверх списка, и именно этого не хватает. Второй сценарий — переезд на новый
телефон целиком: экспорт выбранных аккаунтов в Google Authenticator пачкой
QR-кодов, как это делает сам Google Authenticator («Перенос аккаунтов → Экспорт»).

Результат уходит в апстрим `authenticator-sh/2fa`: issue + PR на каждую часть.

## Цели

1. **Перенос одного аккаунта** — на экране «Поделиться» появляется блок
   постоянного переноса: QR-код с `otpauth://`-ссылкой аккаунта (с секретом).
2. **Экспорт в Google Authenticator** — в экспорте новый вариант: выбор
   аккаунтов галочками (по умолчанию все), «Далее», серия QR-кодов
   `otpauth-migration://` по 10 аккаунтов на код.

## Не цели

- Шаринг Steam по ссылке и вообще любые изменения для Steam. Кнопки
  «Поделиться» у Steam нет и не появится, значит переноса одного Steam-аккаунта
  через QR в этой работе тоже нет (решение пользователя: «по Steam skip»).
- Импорт — уже есть.
- Копирование `otpauth://`-ссылки в буфер, сохранение QR как картинки —
  только показ на экране.
- Изменения сайта `authenticator.sh`.

## Анти-цели (что будет провалом, даже если работает)

- Аккаунт молча не попал в экспорт. Каждый пропуск называется на экране.
- QR, который Google Authenticator читает, но даёт неверные коды (потерян
  период/цифры/алгоритм). Несовместимое не кладём в migration-QR вообще.
- Новые разрешения в `manifest.json`, новые сетевые запросы, новые зависимости.
- Секрет в логах (`console.*`) или в событиях аналитики.
- Блок временной ссылки сломан или заметно усложнён.

## Ограничения

- Правила апстрима (`.github/CONTRIBUTING.md`): сначала issue, одна тема на PR,
  без новых permissions/endpoints/телеметрии, `npm run verify` зелёный.
- Попап максимум 600px по высоте, ширина ~360px.
- 20 локалей в `src/utils/locales/*.ts`, набор ключей типизирован в
  `src/utils/i18n-keys.ts` — каждый новый ключ во всех 20 файлах, иначе `tsc` падает.
- Защита — на уровне всего расширения (пароль хранилища). Отдельных подтверждений
  перед показом QR не делаем: секрет и так виден кнопкой-глазом в
  «Редактировать» без повторного ввода пароля.
- QR рисуется на белом фоне в обеих темах (как в `ShareModal`): инвертированный
  QR камеры читают хуже.

## Подходы (что рассматривали)

Для переноса одного аккаунта:

- **А. Два блока на экране «Поделиться» + оверлей с QR — выбран.** Сверху
  «Временный доступ по ссылке» (текущая форма), ниже компактная строка
  «Перенос в другое приложение» с иконкой QR. Нажатие открывает крупный QR
  поверх экрана. Плюс: разница «временно / постоянно» видна сразу, по высоте
  добавляется одна строка, а оверлей переиспользуется в экспорте.
- Б. Переключатель вкладок вверху «Поделиться». Отклонён: функция прячется за
  вкладкой. Пользователю А и Б были равноценны, выбор оставлен за нами; оверлей
  общий с экспортом перевесил.
- В. Иконка QR на карточке аккаунта. Отклонён: на карточке уже три иконки.

Для экспорта: формат Google Authenticator (`otpauth-migration`) — единственный,
который GA принимает пачкой. Альтернатива «серия обычных `otpauth://` QR по
одному» отброшена — это тот же перенос по одному, только неудобнее.

## Решения пользователя

- Перенос одного аккаунта живёт на экране «Поделиться», отдельным блоком под
  временной ссылкой; QR открывается поверх по кнопке-иконке, без лишнего шага
  «Сгенерировать».
- Экспорт в Google Authenticator с выбором аккаунтов, как в самом GA: все
  отмечены по умолчанию, снять ненужные, «Далее» → QR.
- Steam не трогаем.
- Вклад в апстрим: issue и PR.

## Дизайн

### Общий компонент: `QrOverlay`

Новый `src/components/QrOverlay.tsx`. Оверлей поверх текущего экрана:
затемнённый фон (`fixed inset-0 bg-black/40`, как диалог выбора формата
экспорта), по центру карточка:

```
┌──────────────────────────────┐
│ OpenAI: bukshink7@gmail.com  │  ← подпись (accountLabel) / «Аккаунты 1–10»
│   ┌──────────────────────┐   │
│   │      ▄▄▄ QR ▄▄▄      │   │  белый фон, quiet zone = padding
│   └──────────────────────┘   │
│ Отсканируйте в приложении-   │
│ аутентификаторе на телефоне. │
│ ⚠ Кто отсканирует — получит  │
│   постоянный доступ к кодам. │
│ [‹ Назад]   2 из 3  [Далее ›]│  ← только для серии
│          [ Готово ]          │
└──────────────────────────────┘
```

- Принимает список «кадров» `{ caption: string; text: string }[]`; один кадр —
  без навигации.
- QR рисуется существующим `drawQR` (`src/utils/qr-encode.ts`), SVG.
- Закрытие: Esc (через `useEscapeLayer`, как остальные слои), клик по фону,
  кнопка «Готово». `role="dialog"`, `aria-modal`, фокус внутрь и обратно.
- Если `drawQR` бросил (payload слишком длинный) — вместо QR текст ошибки,
  остальное работает.

### Часть 1: «Поделиться» → перенос одного аккаунта (PR 1)

Изменения в `src/components/ShareModal.tsx`:

- Заголовок экрана `share.title`: «Поделиться кодами» → «Поделиться» (во всех
  локалях — смысл «поделиться», без «кодов»). Тот же ключ — подсказка кнопки
  на карточке, это ок.
- Над текущей формой — подзаголовок секции «Временный доступ по ссылке».
- Под формой (только на первом шаге, пока ссылка не создана) — разделитель и
  секция «Перенос в другое приложение»: строка-кнопка

  ```
  ─────────────────────────────────
  ПЕРЕНОС В ДРУГОЕ ПРИЛОЖЕНИЕ
  [▦]  Показать QR-код
       Google Authenticator, Aegis и др.
       Доступ будет постоянным.
  ```
  Иконка `QrCode` из `lucide-react`. Нажатие открывает `QrOverlay` с одним
  кадром: `caption = accountLabel(account)`, `text = buildOTPAuthURL(account)`.
- Если у аккаунта нестандартные параметры (период ≠ 30, цифр ≠ 6, не SHA1) —
  в оверлее дополнительная строка *(наше решение)*: «Нестандартные параметры
  (период 60 с) — не все приложения их поддерживают; Google Authenticator может
  показывать неверные коды». QR всё равно показываем: ссылка несёт все
  параметры, Aegis/2FAS их соблюдают. Ключ `qr.nonStandard`.
- `buildOTPAuthURL` (`src/utils/qr-parser.ts:323`) уже есть и покрыт
  round-trip-тестом — новая логика сборки не нужна.
- Кнопка «Поделиться» на карточке по-прежнему скрыта для Steam и «битых»
  записей — не меняем.

Новые i18n-ключи (примерно): `share.temporaryTitle`, `share.transferTitle`,
`share.transferShow`, `share.transferHint`, `qr.scanHint`, `qr.permanentWarning`,
`qr.done`, `qr.next`, `qr.prev`, `qr.position` (`{0} из {1}`), `qr.failed`.

### Часть 2: экспорт в Google Authenticator (PR 2)

**Кодировщик.** `src/utils/migration-parser.ts` уже разбирает
`otpauth-migration://offline?data=…` (protobuf вручную). Добавляем обратную
функцию в тот же файл (по образцу пары `parseOTPAuthURL`/`buildOTPAuthURL`:
«один формат с двух концов»):

```ts
export function buildMigrationURLs(accounts: Account[]): {
  urls: string[];          // по одному на QR, ≤ 10 аккаунтов в каждом
  skipped: Account[];      // не совместимы с форматом
};
```

- Поля `MigrationPayload`: `otp_parameters` (secret bytes, name, issuer,
  algorithm, digits, type=TOTP), `version=1`, `batch_size`, `batch_index`,
  `batch_id` (случайный int32, один на всю серию).
- Секрет: base32 → байты (функция декодирования base32 в проекте есть в
  `totp`/`otpauth`; использовать существующую).
- Совместимы *(наше решение, осторожное)*: TOTP, период 30, 6 цифр, SHA1, не
  Steam — то, что Google Authenticator гарантированно считает верно. В формате
  нет поля периода, поэтому период ≠ 30 нельзя вовсе. 8 цифр и SHA256/SHA512
  формат передаёт, но поддержка в GA на iOS/Android исторически неровная;
  неверные коды без симптомов хуже пропуска. Поэтому они идут в `skipped` с
  причиной «нестандартные параметры — перенесите через „Поделиться“ в Aegis/2FAS».
  Правило вынесено в одну функцию `isMigrationCompatible(account)` — если
  проверка на устройстве (шаг в плане) покажет, что GA их понимает, правило
  расширяется в одном месте.
- 10 на QR — как у самого GA; заодно держит QR читаемым с экрана.
- Тест: `parseMigrationURL(buildMigrationURLs(x).urls[i])` возвращает те же
  аккаунты (round-trip), батчи пронумерованы, несовместимые в `skipped`.

**UI.** В диалоге выбора формата экспорта (`src/components/ExportImport.tsx`,
`showExportChoice`) — ещё одна карточка «В Google Authenticator» с подсказкой
«QR-коды для приложения на телефоне» и кнопкой «Выбрать аккаунты». Карточка
ставится последней; диалог уже прокручивается (`max-h-full overflow-y-auto`).

Нажатие закрывает диалог и открывает полноэкранный экран (как «Поделиться»:
`fixed inset-0`, `ModalHeader` со стрелкой назад) — новый компонент
`src/components/TransferExport.tsx`:

```
← В Google Authenticator
 Выбрано 12 из 14            [Снять все]
 ☑ OpenAI: bukshink7@gmail.com
 ☑ GitHub: gentslava
 ☐ Steam: login           нельзя: Steam
 ☐ Bank: 123              нельзя: период 60 с
 …
 [        Далее (12)        ]
```

- Источник — те же аккаунты, что идут в обычный экспорт (`exportAccounts()`),
  с тем же предупреждением про аккаунты, удержанные хранилищем
  (`quarantinedCount()`), чтобы поведение экспорта не расходилось.
- Все совместимые отмечены по умолчанию; несовместимые показаны неактивными
  с причиной, а не спрятаны.
- «Выбрать все / Снять все» переключателем. «Далее» неактивна при 0 выбранных.
- «Далее» → `QrOverlay` с кадрами `urls`, подпись кадра «Аккаунты 1–10 из 12»,
  навигация «Назад/Далее», позиция «1 из 2». На последнем кадре текст
  «Убедитесь, что отсканированы все N кодов».

Новые i18n-ключи: `export.ga`, `export.gaHint`, `export.gaChoose`,
`transfer.title`, `transfer.selected` (`{0} из {1}`), `transfer.selectAll`,
`transfer.selectNone`, `transfer.next` (`{0}`), `transfer.skipSteam`,
`transfer.skipPeriod`, `transfer.skipParams` (цифры/алгоритм), `transfer.batchCaption`,
`transfer.lastHint`.

## Поставка в апстрим

База: `main` форка совпадает с `authenticator-sh/2fa` main (`d19bc92`, проверено
2026-11-12). Перед началом добавить remote `upstream` и ветвиться от
`upstream/main`; перед открытием PR — rebase на свежий `upstream/main`.
Внешних PR в апстриме ещё не было ни одного.

Публикация issue/PR — действие от имени пользователя и необратимо: тексты
готовятся заранее и показываются пользователю, публикуются после его «да».

**Ветки в форке `gentslava/2fa`** (решение пользователя, стандарт для его форков):

- `main` — чистое зеркало `upstream/main`, своих коммитов не содержит.
- `master` — наша сборка: создаётся от `main`, в неё вливаются наши фича-ветки.
  Из неё собираем своё расширение (`npm run build` → `dist/`, загрузка
  распакованным в `chrome://extensions`), не дожидаясь апстрима.
- Фича-ветки `feat/share-qr-transfer` (часть 1, от `main`) и
  `feat/export-google-authenticator` (часть 2, от части 1) — из них PR в
  `authenticator-sh/2fa:main`.

**Порядок для каждой части:** issue → сразу PR с `Closes #N` в описании →
комментарий в issue со ссылкой на PR. Не ждём ответа мейнтейнера: даже если PR
не примут, работа живёт в нашем `master`.

1. Issue «Show an account's QR code to add it to another authenticator» —
   с описанием части 1 и сценарием «как было в старом расширении». Скриншоты
   `gh` загрузить не умеет — пользователь при желании прикрепит их в вебе.
2. Issue «Export to Google Authenticator via migration QR codes» — часть 2.
3. PR 1 (часть 1, включает `QrOverlay`) → PR 2 (часть 2) поверх части 1; в
   описании PR 2 сказано, что он зависит от PR 1.
4. Описания PR — по `.github/PULL_REQUEST_TEMPLATE.md`, на английском; issue
   тоже на английском. Сообщения коммитов — в стиле репозитория.
5. Этот документ в PR не попадает: коммитится только в `master` форка.

## Решения, оставленные исполнителю

- Точные формулировки строк на 20 языках (ru и en — вычитать особенно; остальные
  — аккуратный перевод в духе существующих строк).
- Вёрстка и классы Tailwind — в стиле соседних компонентов.
- События `track(...)`: новых не добавляем (CONTRIBUTING: «No telemetry»);
  если существующие вызовы в `ShareModal` мешают — не трогать.
- Тесты: юнит-тесты в `test/` в стиле `test/share.test.ts` и
  `test/totp.test.ts` (собственный раннер, регистрация в `test/run.ts`);
  e2e — по желанию, если простая проверка «открыть Поделиться → QR виден».
